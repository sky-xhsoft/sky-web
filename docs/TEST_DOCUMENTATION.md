## 📊 测试数据生成规则

### 动态表单测试数据生成

测试脚本会根据字段类型自动生成测试数据：

| 字段类型 | 生成规则 | 示例 |
|---------|---------|------|
| text | `测试数据_${时间戳}` | `测试数据_1705654321000` |
| textarea | `测试备注_${时间戳}` | `测试备注_1705654321000` |
| number | 随机整数 (0-1000) | `567` |
| select | 固定值 `'Y'` | `Y` |
| checkbox | 固定值 `'Y'` | `Y` |
| date | 当前日期 | `2026-01-19` |
| datetime | 当前日期时间 | `2026-01-19T10:30:00.000Z` |
| 其他必填字段 | `测试_${时间戳}` | `测试_1705654321000` |

### 系统字段处理

以下系统字段会被自动跳过，不生成测试数据：
- `ID`
- `CREATE_BY`
- `CREATE_TIME`
- `UPDATE_BY`
- `UPDATE_TIME`

## ⚠️ 常见问题

### 1. 登录失败

**错误信息**: `❌ 登录失败，无法继续测试`

**原因**:
- 后端服务器未启动
- 用户名或密码错误
- 数据库连接失败

**解决方法**:
```bash
# 检查后端服务器
curl http://localhost:9090/api/v1/health

# 检查测试用户配置
# 在 test-cloud-module.js 中修改 CONFIG.TEST_USER
```

### 2. 部分测试失败

**情况 1**: 云盘测试通过，动态表单测试失败

**原因**: 数据库中没有元数据配置（sys_subsystem, sys_table_category, sys_table, sys_column）

**解决方法**:
- 运行数据库初始化脚本
- 或手动创建测试用的元数据配置

**情况 2**: 动态表单配置测试通过，数据 CRUD 测试失败

**原因**: 目标数据表不存在或表结构与配置不匹配

**解决方法**:
- 确保 sys_table.TABLE_NAME 对应的物理表存在
- 确保 sys_column 配置与表结构一致

### 3. 批量操作失败

**错误信息**: `批量删除部分失败`

**原因**:
- 文件夹包含子项（文件或子文件夹）
- 权限不足
- 数据库约束冲突

**解决方法**:
- 检查后端日志
- 确认用户权限
- 检查数据库外键约束

### 4. 字段验证测试失败

**情况**: 应该拒绝无效数据，但创建成功了

**原因**: 后端字段验证未实现或验证规则有误

**解决方法**:
- 检查后端 validation 中间件
- 确认 sys_column.NULL_ABLE 配置正确
- 验证后端是否正确读取并应用验证规则

## 📈 测试结果分析

### 通过率指标

- **100%**: 优秀，所有功能正常
- **90-99%**: 良好，少数功能需要修复
- **80-89%**: 一般，多个功能需要修复
- **<80%**: 较差，需要全面检查

### 失败测试分析

如果有测试失败，脚本会在最后输出失败详情：

```
失败的测试详情:

1. 测试 #15: 获取元数据子系统列表
   错误: 返回数据格式错误

2. 测试 #22: 创建表单数据
   错误: 缺少必填字段 'NAME'
```

根据失败信息：
1. 定位到对应的测试函数
2. 检查 API 返回数据
3. 对比预期结果
4. 修复后端或前端代码
5. 重新运行测试

## 🔧 自定义测试

### 修改测试用户

编辑 `test-cloud-module.js`:

```javascript
const CONFIG = {
  API_BASE_URL: 'http://localhost:9090/api/v1',
  FRONTEND_URL: 'http://localhost:5181',
  TEST_USER: {
    username: 'your_username',  // 修改为你的用户名
    password: 'your_password',  // 修改为你的密码
    clientType: 'web',
    companyId: 1  // 修改为你的公司ID
  }
};
```

### 跳过某些测试

注释掉不需要的测试：

```javascript
// 跳过云盘模块测试
// await test02_ListRootItems();
// await test03_CreateFolder();
// ...

// 只运行动态表单系统测试
const subsystems = await test15_GetSubsystems();
// ...
```

### 添加新测试

参考现有测试函数的格式：

```javascript
/**
 * 测试 30: 你的测试名称
 */
async function test30_YourTestName() {
  logTest('你的测试描述');

  try {
    const response = await request('GET', '/your/api/endpoint');

    if (response.code === 200 && response.data) {
      logPass('测试通过');
      return response.data;
    } else {
      logFail('测试失败', new Error('返回数据格式错误'));
      return null;
    }
  } catch (error) {
    logFail('请求失败', error);
    return null;
  }
}
```

然后在 `runTests()` 函数中调用：

```javascript
// 在主测试流程末尾添加
await test30_YourTestName();
```
